# KE ↔ W3 합성 러너 설계 — "ge 0 인 동안은 KE, 걷는 동안만 W3" (초안 2026-10-07 17:10, claude2)

> 상태: **설계 문서. 구현 전.** 근거 실험 X1·X2(TRANSITION_W3KE.md §1c)가 통과해야 구현에 들어간다. 구현은 로컬·기본 꺼짐·셀프테스트 포함이며
> 젯슨 배포·서비스 변경·실물 시험은 승인 사항이다(CLAUDE.md). 시뮬 수치는 실물 성공 확률이 아니다.

## 1. 왜 이 구조인가 (측정 근거, 지연 2)
| 사실 | 수치 | 출처 |
|---|---|---|
| 정책 교체 방식(재기동 / 러너 리셋 / 상태 이어받기)은 낙상이 같다 | b18 4.7 / 4.7 / 3.8 %, sf15 17.1 / 15.8 / 17.7 %, 무외란 0 | TRANSITION §5.2 |
| hot-swap 과도는 슬루 안 | 첫 틱 목표 점프 1.1°, \|ω\| p95 0.40 rad/s | §5.2 |
| 재기동의 수동 홀드 창은 최약 상태 | 홀드 중 뒤 18 N 낙상 59.2 % (W3 STAND 12.3 %, KE 1.7 %) | §5.5 |
| W3 STAND 는 KE 보다 밀기에 약하다 | b18 12.0 vs 4.7 %, sf15 99.7 vs 17.1 % | §5.1, STAND_MODE_CMP |
| KE → W3 는 세 방식 모두 깨끗 | 낙상 0/316, 선행조건 0.98 s, 첫 이륙 0.22 s | §5.3 |
| 밀린 직후 정지는 해롭다 | 앞 12 N: 계속 걷기 25.0 % vs stop 53–56 % | §5.4 |
→ 프로세스 재기동과 W3 STAND 구간을 없애고, 전환을 gait 래치(켜기 수락 틱 / 반주기 경계 꺼짐 틱)에 묶는다.

## 2. 구조
```
            step 켜기(감독기 선행조건 통과 + KE 회복 모드 꺼짐)
   KE  ───────────────────────────────────────────────▶  W3 (걷기·회전)
 (G21a 서기 + G24Ra 회복                                  (W3S3d, ge 1)
  + 감지기)        ◀───────────────────────────────────
            stop / step 끄기 → 반주기 경계 ge 0 래치
```
- 세션 시작(`stand`) = 홀드 → KE 인계(기존 경로·기존 근거 그대로: 워밍업·온셋 블렌딩 1.5 s).
- 브리지 노드에서 보면 **W3 세션 그대로**다(체크포인트 키가 W3 키 집합에 속함): `step` 명령·seq·ack·정지 래치·켜기 선행조건(양발 1.0 s·기울기 ≤ 7°·\|ω_xy\| < 0.25 1.0 s)·헤딩 고리·명령 범위가 그대로 적용된다.
  바뀌는 것은 "ge 0 일 때 어떤 정책이 서는가" 하나다.
- 프로세스·ROS 토픽·stage8 스트림은 끊기지 않는다(수동 홀드 창 없음, 블렌딩 없음).

## 3. 러너 계약 (`rl_walking/deploy/kew3_runner.py`, 새 파일)
`KeW3Runner(w3: PolicyRunnerStage4(w3=…), ke: C5Runner)` — 브리지가 쓰는 러너 인터페이스(step·reset·set_gait_enable·_w3_clock·last_obs·last_action·blackbox …)를 그대로 낸다.
| 사건 | 동작 | 시뮬 대응 |
|---|---|---|
| reset() | 두 러너 reset, 모드 KE, want False | 홀드→KE 인계(sab 하네스) |
| KE 모드 틱 | `ke.step()` (감지기·회복 전환·cue 그대로) | KE |
| KE 모드에서 want True | **이 틱에** W3 로 전환: `w3.reset()`(이력 첫 틱 백필·last_action 0·EMA 재시작·클록 리셋) + 슬루 기준 `w3._prev_emitted ← ke 의 마지막 방출 목표` + `w3.set_gait_enable(True)` → `w3.step()` | X1 `--ke_mode reset --pre_*_s 0` |
| W3 모드 틱 | `w3.step()` (클록 래치·리드 발 규칙·헤딩 고리 명령 그대로) | W3 |
| W3 모드에서 want False 이고 이번 틱 뒤 클록 ge 0 | **다음 틱부터** KE: `ke.reset()`(이력 백필·last_action 0·EMA·감지기 새로 — 기준 자세 1.5 s 추종) + 슬루 기준 이어받기 | X2 `--settle fixed --settle_s 0` (1 틱 차 — 시뮬은 래치 틱에 KE) |
- 이어받는 것은 **슬루 기준(직전 방출 목표)** 하나뿐이다. 러너 reset 은 첫 틱에 실측 qpos 를 슬루 기준으로 쓰는데, 실물은 명령–엔코더 추종 오차가 수 도라 그대로 두면 전환 틱에 목표가 그만큼 끌려간다. 시뮬 reset 팔은 체인(슬루·LPF)이 연속이었다.
- 노드의 LPF(`tgt_filt`)·발진 가드·리프트 가드·워밍업·블렌딩 상태는 건드리지 않는다(전환은 러너 안의 일).
- 관측 레이아웃(320)·기본자세·관측 필터 β·클록 주파수가 두 러너에서 같아야 한다(다르면 생성 거부).

## 4. 노드 변경 (최소)
- 새 체크포인트 키(예 `stand_kew3_g21a_g24ra_w3s3d15800`)는 `--experimental-w3` + 새 플래그 `--experimental-kew3` 일 때만 등록. 꺼져 있으면 키 자체가 없다(종전 경로 비트 동일 — 기존 셀프테스트로 확인).
- 켜기 선행조건에 한 줄 추가: KE 회복 모드가 켜져 있으면 거부(사유 표시). 그 밖 판정·래치·ack 는 종전 W3 감독기 그대로.
- 블랙박스: `kew3`(모드·전환 사건) + 기존 `c5`·`w3` 필드. 콘솔 미노출(기동 인자).
- KE 종료 판정(imu / imuH)은 KE 설정값 하나(조기 복귀 유지 0.2 / 0.7 s) — STOPEST §17 결과와 사용자 결정에 따른다.

## 5. 검증 계획
1. 시뮬 근거: X1(KE → W3 즉시 켜기)·X2(래치 즉시 KE) 통과 — **구현 착수 조건**. 이어서 지연 3·4, 외란(b18·sf15) 조건.
2. 단위 셀프테스트(numpy, 스텁 정책): 모드 전환 틱·슬루 연속(전환 틱 |Δ목표| ≤ 슬루)·reset 의미(이력·last_action·EMA·클록·감지기)·불일치 계약 거부·꺼진 경로 불변.
3. 노드 셀프테스트(가짜 ROS): stand → step on → 걷기 → stop → KE → 다시 step on, seq·정지 래치·회복 모드 중 켜기 거부.
4. 롤아웃 동치: 시뮬 전환 추적(eval_transition `--trace_all`)의 관측을 합성 러너에 재생해 행동이 float 수준에서 같은지(기존 `selftest_w3_rollout_parity.py` 방식).
5. 회귀: `reports/regress/run_regress.sh --mode quick`(W3·KE 경로 불변 확인).

## 6. 이 구조가 풀지 않는 것
- 걷는 중 외란: 계속 걷기가 기본이고(앞 밀기), 뒤 밀기는 KE 즉시 인계가 낫다(오라클 시점 9.8 vs 21.1 %). 관측 기반 감지기는 Q6 에서 따로 판정한다. 합성 러너에는 `force_ke()`(래치를 기다리지 않는 인계) 자리만 둔다 — 감지기가 통과하기 전에는 호출하지 않는다.
- W3 걷기 자체의 sim-to-real 간극(지연 ≥ 5 틱, IMU 피치 편향 × CoM, 발목 유격): ROBUST_DESIGN.md.
- 세션 전체 방향 기준(heading): 걷기 시작마다 기준을 새로 잡는다(현행). 세션 기준 보존은 별도 과제.
