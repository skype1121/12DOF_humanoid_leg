# G16 설계안 v2 (2026-10-01 02:3x) — 검토 3건(방법론·구현 위험·레드팀) 반영

## 0. v1 → v2 에서 바뀐 것
1. **아침 결정용 평가를 먼저 돌린다** (레드팀). 아침 실물 정책은 어차피 G12-9500이고, G16은 실측 지연 전에는 시험 후보가 될 수 없다.
   - G12-9500(v2 관측) 기준선을 보강한다: d6 무외란·뒤 8 N·뒤 18 N, d1 뒤 18 N.
   - **지연 조회표**를 만든다: d0·2·4·5 × {무외란, 뒤 8 N}. 기존 d1·3·6·11과 합치면 아침 실측 지연을 곧바로 시뮬 기대치로 읽을 수 있다.
   - 후순위: OSC 재현을 v2 관측으로 다시 돌린다(d11·d14 × {무외란, 앞 8 N, 뒤 8 N}, `--dump_envs 6`). 기존 legacy 결과와 인자가 같아서 단일 변수 A/B가 된다.
2. **러너 EMA 계약 모드를 준비한다** (레드팀·구현 검토). 정책의 env.yaml에서 joint_vel_ema 함수 이름으로 계약(legacy/v2)을 판별한다.
   legacy로 학습된 정책(G12 계열)에는 이 채널을 0으로 넣는 선택지(`ema0`)를 둔다. **젯슨 배포와 기본 동작 변경은 아침에 승윤님이 결정한다.** 오늘 밤은 구현과 오프라인 검증까지만 한다.
   - 새 근거 (시뮬, 단일 변수 대조): G12-9500에서 관측만 v2(실물형 EMA)와 legacy(학습 계약)로 바꿨다. DR 표본은 311쌍이 같다.
     - 무외란과 8 N은 같다.
     - **d3 뒤 18 N 낙상은 44.7 → 52.1 %**(v2 쪽만 넘어진 env 56개, legacy 쪽만 33개, McNemar p = 0.019).
     - 흔들림이 클 때 학습 분포 밖 입력이 해롭다는 쪽을 가리킨다.
   - 레드팀 반사실(0929 실물 로그, 개루프): EMA를 0으로 바꾼 명령 차이는 흔들림 시작 구간에서 ≤ 0.14°였다. 2 Hz 큰 흔들림 구간에서는 발목롤 22° RMS였다.
     따라서 **흔들림 시작은 설명하지 못하고, 키우거나 유지했을 수 있다** (가설).
3. **후보를 줄이고 복제한다** (방법론·레드팀).
   - 넣는 것: G16o(seed 42·43), G16a(seed 42·43), G16d(seed 42, 실측 뒤 판정).
   - **G16i는 뺀다.** 판정 축(18 N)을 학습에서 키우는 시험 맞춤이다.
   - **G16c는 보류한다.** 구현 검토 결과, 크리틱 미러 사양(15 고정)이 첫 PPO 업데이트에서 ValueError를 낸다. 웜스타트는 엄격 로드라 크기 불일치가 나고, 체크포인트 크리틱 꼬리 확장과 Adam 패딩, 평가 로드 경로도 없다.
4. **판정을 강화한다** (방법론·레드팀).
   - 체크포인트 4개를 고정하고, 학습 seed를 복제하고, 평가 seed 짝 비교를 한다.
   - C0에 d6·d11·토크 포화·부호반전·발 들기를 넣는다. C1 문턱은 max(15 %p, 2σ_ck)이고 seed 폭을 넘어야 한다.
   - 가설 판정과 배포 판정을 분리한다. 사후 선택은 금지한다.
5. **v1 표기를 정정한다** (레드팀).
   - stage8 적체 수정: "완료" → **벤치 검증 완료, 실물 미검증**.
   - LIP "스텝 필수"는 점질량 가정 **계산값**이다. 발목·힙 전략과 밀기 중 CoP 이동은 뺐다.
   - §0.3 게인 상관: legacy에서 EMA 채널은 잡음만 받아 피드백이 될 수 없었다. 그래서 그 채널 게인과 18 N의 상관은 전체 게인 크기의 대리였고, **교란된 상관**이다. G16d의 인과 근거는 G15d 단일 변경뿐이다.
   - **"G16o = 관측 수정만"은 부정확했다.** joint_pos·joint_vel·joint_vel_ema 세 함수를 바꾼다. 확인 결과는 다음과 같다(단위시험 `test_v2_equals_legacy_pos_and_first_vel_except_reset_edge`).
     - 유격 0에서는 위치와 (먼저 부르는) 속도가 리셋 가장자리를 빼면 legacy와 같다.
     - 차이 ①: joint_vel_ema가 실제 속도의 EMA다(핵심).
     - 차이 ②: 리셋 뒤 둘째 틱에서 legacy 속도는 0이다.
     - 차이 ③: 리셋 첫 틱에 v2는 ref = q로 둔다. legacy는 유격이 있으면 이전 목표를 쓸 수 있다.
     - env.yaml 차이는 이 3줄뿐이다(구현 검토 확인). 크리틱은 base_lin_vel만 따로 받으므로 EMA 이중 갱신은 없다(확인).

## 3. 러너 EMA 계약 모드 (준비만, 배포는 아침 결정)
- `policy_runner_stage4`: `jvel_ema_mode ∈ {v2, ema0}`. ema0이면 joint_vel_ema 프레임을 0으로 넣는다. 이 값은 학습 분포 평균으로, 학습 때는 0 + 잡음 std 0.04였다.
- 브리지: env.yaml의 joint_vel_ema.func가 `encoder_joint_vel_ema`면 legacy 계약, `_v2`면 v2 계약으로 파싱한다.
  - 시작 로그와 블랙박스에 모드를 기록한다.
  - G16 계열(v2 계약)에 ema0을 쓰면 기동을 거부한다(반대 방향 결함 방지).
- 검증 계획:
  - selftest: ema0이면 obs[260:320] = 0, 나머지 260차원은 v2와 비트 동일.
  - 0929 로그 재생: 러너 출력 = 오프라인 π(EMA 0).
  - MANIFEST md5 갱신.
- 아침 선택지:
  - (A) 현 상태 v2: 0929와 지연만 다른 깨끗한 대조.
  - (B) ema0: 학습 계약 복원. 시뮬에서는 무외란이 같고 큰 밀기에서 낫다.
  - 두 번 시험한다면 A → B 순서로 하는 것을 제안한다. 1회로는 통계 판정이 불가능하므로 계약 원칙과 반사실을 함께 본다.
- 남은 불일치 (구현 검토, 현장 확인 필요): 브리지 qvel 추정기가 값이 안 바뀐 틱에 0을 내고, 바뀐 틱에 Δq/(틱×머문 틱 수)를 낸다.
  0929 로그에서는 같은 qpos가 55–85 %였다(정지 양자화 포함). 이 로그는 stage8 수정 전 것이다. 아침 로그로 갱신 누락률을 다시 재고,
  필요하면 관측 샘플홀드 평가 팔을 추가한다.
