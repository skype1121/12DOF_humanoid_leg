# 기립 시험 콘솔 리뉴얼 — 2026-09-11

로컬 구현·오프라인 검증용 개편이다. 젯슨 배포, 서비스 재시작, CAN 송신,
영점 변경, 모터 조작은 수행하지 않았다. 정책·학습·제어기 가드도 변경하지 않았다.

## 화면과 실행

- **운영**: 현재 단계, 다음 허용 동작, 막힌 이유, 실제 명령 주체, IMU 추이,
  좌우 접촉/미확인, 무보조 관측 시간, 현장 이벤트, 회수 순서.
- **설정·점검**: 접지 후 인계 / 공중 정책 시작을 명시 선택하고 단계별 응답 확인.
  기본 정책 `stand_hang_v5`는 유지했다. 개편이 정책 승격을 의미하지 않는다.
- **기록·분석**: 세션·프로세스 로그, 메모/영상 식별자, 같은 프레임의 관절 추종 오차.
  분석은 해당 시험 브리지가 보고한 파일만 사용하며 최신 로그로 대체하지 않는다.

장비와 분리된 미리보기:

```bash
python3 jetson/scripts/operator_console.py --demo --port 18800
```

`http://127.0.0.1:18800`으로 접속한다. 데모는 강제로 loopback에 바인딩하고
ROS 초기화·CAN 검사·프로세스 실행·제어 마커 생성을 하지 않는다. 합성 기록은
시작 시 출력되는 `/tmp/humanoid-console-demo-*`에 남는다. 데모의 ‘착지 기록’만
합성 접촉을 켠다. 실물 모드의 이벤트 버튼은 기록만 하며 접촉을 바꾸지 않는다.

실물 모드는 기존 실행 경로를 유지했다. 인증 서비스가 아니므로 신뢰된 내부망
전용이며 인터넷에 노출하지 않는다. 브라우저 교차 출처 요청은 거부한다.
이번 작업에서 실물 모드는 실행하지 않았다.

## 서버 계약

브라우저가 아니라 서버의 `TrialState`가 단계를 관리한다. 서버 부팅 ID, 상태
리비전, 요청 ID로 오래된 탭·중복 요청을 거부/중복 억제한다. HTTP 요청 접수와
실제 응답 확인을 구분한다. 프런트엔드에는 자체 ‘완료’ 목록이 없다.

| 단계 | 완료 근거 |
|---|---|
| 센서 | 정상 형태·유효한 타임스탬프의 IMU 및 좌우 접촉 수신 |
| 인수 대기 | 새 stage8 `takeover.waiting` 응답과 추적 프로세스 생존 |
| 자세 유지·게인 | 해당 프로세스의 신선한 단계/게인 출력 |
| 핸드오프 | hang_stand 종료코드 3 + 새 stage8 `takeover.holding`, 12축 |
| 기준점·ARM | 명령 프로세스 정상 종료 + 새 응답·명령 순번·명령명·수락 상태 |
| 정책 로드 | 생존하는 브리지의 실제 LIVE 기동 출력에 기록된 정책명 |
| 정책 시작 | 새 브리지 활성 응답 + 새 stage8 ARM/실행 응답 + 정책명 일치 |
| 프로세스 종료 | 콘솔 추적 제어 프로세스·명령 재시도 도구 종료 및 상태 수신 만료 |
| 토크 해제 요청 | 릴리즈 정상 종료 + 전송 완료 출력, 피드백/송신 오류 출력 없음 |

브리지는 정책 시작 전에는 주기적 debug를 내지 않으므로 ‘정책 로드’는 기동
출력으로 확인한다. 이후 실제 debug의 정책명도 대조한다. 로그 문자열 계약이
바뀌면 콘솔은 완료 확인을 보류/시간 초과 처리하므로 함께 갱신해야 한다.

센서 표시용 신선도 한계는 1.5초다. 이것은 하위 제어기의 더 빠른 정지 가드를
대체하거나 완화하지 않는다. 타임스탬프는 같은 장비의 epoch 초 계약이다.
미보정 발력은 화면·진행·성공 판정에 쓰지 않는다. 구 분석 호환용 `pct`/`fn`
로그 필드는 남겼지만 `unverified_force_fields: true`로 표시했다.

## 정지·회수와 판정의 한계

- ‘정지 요청’은 `estop`과 `STOP_ALL`을 발행한다. 센서·기록·단계 검사로
  차단하지 않는다. 추적 중인 ARM/기준점 재시도 송신자에는 종료 신호를 보낸다.
  **하드웨어 비상정지나 모든 송신자의 정지 보증은 아니다.** ROS/프로세스 지연,
  외부 송신자, 이미 진행 중인 요청은 실제 상태를 확인해야 한다.
- 새 STOP_ALL 명령 순번·수락·`running=false`가 와야 ‘제어기 목표 동결 확인’이다.
  토크 유지 상태이며 토크 해제와 다르다. 정지 전 응답은 인정하지 않는다.
- 회수는 운영자 줄 지지 확인 → 콘솔 소유 제어/명령 프로세스 종료 → 릴리즈.
  로컬의 알려진 외부 제어 프로세스가 있거나 검사가 실패/만료되면 릴리즈를
  허용하지 않는다. 원격·미등록 송신자의 부재까지 증명하지는 않는다.
- 릴리즈 스크립트는 오류를 출력하면서 종료코드 0을 반환할 수 있으므로 종료코드만
  믿지 않는다. 전송 완료 출력도 **실제 모터 무토크 상태의 센서 검증은 아니다.**
  오류 시 새 시험 진행을 차단하고 현장 확인을 요구한다.
- 기록 실패는 새로운 제어 시작을 차단한다. 정지와 명시적인 회수는 기록보다
  우선하며, 기록이 불가능해도 기존 줄 지지·프로세스 종료 조건 아래에서 허용한다.
- 서버 재시작 시 이전 프로세스를 자동 인수·종료하지 않는다. 기존 소유 콘솔이나
  터미널에서 상태를 확인해야 한다. 브라우저 재접속은 서버의 시험 상태를 유지한다.

무보조 시간은 운영자가 **모든 줄 느슨·외부 보조 없음**을 확인한 뒤 시작한다.
5초/30초는 관측 시간 도달 표시에 불과하다. 접촉 상실·센서 소실·정책 중단·
재인장·보조 시 해당 시도를 중단하고 새 시험 전에는 다시 측정하지 않는다.
보조/줄 상태 확인은 자기보고이므로 영상과 대조해야 한다. 시험별 허용 자세·
각속도 기준과 줄 상태를 검토하기 전에는 자립 성공을 확정하지 않는다.

20Hz 기록은 브라우저와 독립적이며, IMU·접촉 원값/패드 수·관절 실제각/기준점/
명령 상대각·신선도·시험 방식·정책·측정 중단 사유를 남긴다. 관절 상대각은
엔코더 실제각에서 기준점을 뺀 프레임이며 정책 관절 프레임과 혼동하지 않는다.

## 오프라인 검증 재현

```bash
python3 jetson/scripts/operator_console.py --selftest
python3 -m unittest discover -s tests -p test_operator_console.py -v
# 별도 터미널에서 위 --demo 서버 실행 후; 개발 PC에 Playwright/Chromium 필요
python3 tests/console_browser_smoke.py
```

셀프테스트는 실제 ROS 발행·프로세스 실행 없이 임시 디렉터리만 사용한다.
회귀 테스트는 실제 subprocess 경로를 막고 모의 입력으로 검사한다. 브라우저
검사는 API가 `demo=true`인 서버에만 동작한다. 데스크톱/모바일 캡처 경로는
검사 종료 시 출력된다. 전송 스크립트의 출력 계약은 별도 합성 로그로 검증한다.

배포 목록에 `console_state.py`, `console_demo.py`, `console_ui.html`을 추가했다.
단일 `operator_console.py`만 복사하면 안 된다. 패키지 조립/젯슨 배포는 별도다.

현장에 남는 검증: 실제 ROS 메시지 주기·시각 계약, 설치된 스크립트 출력 버전,
인계 직전/직후 목표 연속성·명령 공백, 프로세스 종료 지연, 실제 동결·릴리즈,
영상 동기화 및 무보조 자립. 오프라인 화면/절차 통과는 실물 성공 보증이 아니다.
