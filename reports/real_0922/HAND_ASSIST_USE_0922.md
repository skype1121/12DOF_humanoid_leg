# 손 보조 데이터의 사용 범위 — 0922 3회차 기준

승윤님 질문: "자립 판정으로는 무효지만 이 데이터로 개선할 수 있겠지? 다른 논문들에서도
손으로 위에서 잡아주면서 데이터값을 깎아내서 점점 개선했으니까."

**답: 개선에 쓸 수 있다. 단 항목을 갈라서 쓴다.** 손 보조는 *상태*를 바꾸지만
*상태 → 명령* 사상(정책 자체)과 *명령 → 관절 응답* 사상(플랜트)은 바꾸지 않는다.
바뀌는 것은 몸에 걸리는 외력뿐이고, 그 외력 크기는 모른다. 따라서:

| 쓸 수 있다 (손과 무관하거나, 오히려 표본이 늘어남) | 쓸 수 없다 (손이 값을 직접 만든다) |
|---|---|
| 정책 응답 기울기 d(발목명령)/d(피치) — 손으로 도달한 피치 −12~+16° 구간은 무보조로는 안전하게 못 가본다 | 생존 시간·자립 시간 |
| 명령 → 실측 지연·추종비 (플랜트 식별) | 낙상 여부·회복 여부 |
| 배포 체인 계약(슬루·LPF·블렌딩·소프트 클램프) | 균형 능력·세대 승격 판정 |
| 센서 신선도, 접촉 비트 거동, 소프트 클램프 발생 조건 | 보상·정숙성 점수 |

**논문 방식과 우리 상황의 차이.** 부분 하중 지지를 점진적으로 줄이는 커리큘럼은 표준
방법이 맞다. 단 그 방법들은 보조력을 **계측·제어**한다(하중 제거 비율을 알고 단조 감소).
사람 손은 힘을 모르고 재현도 안 되므로 "깎아낸다"를 정량화할 수 없다. 우리 장비는
행잉 로프가 있으므로, **로프 길이로 지지율을 고정·반복**하면 같은 커리큘럼을 정량적으로
할 수 있다. 손은 낙상 방지용으로만 쓰고, 커리큘럼은 로프로 하는 것이 맞다.

## 실제로 뽑아낸 것 (3회차 로그, 1151틱 23.0 s)

### 1. 관측 계약은 정상이다 — 정책이 시뮬과 같은 방향·같은 크기로 명령한다
같은 정책(G10 model_6600)의 피치 → 발목 명령 응답 기울기:

| | 피치 범위 | d(발목명령)/d(피치) |
|---|---|---|
| 실물 3회차, 인계~2.5 s(무보조) | −3.8 ~ +11.6° | **−1.00 °/°** |
| 실물 3회차, 2.5 s 이후(손 보조) | −12.4 ~ +16.1° | −0.61 °/° |
| 시뮬 명목(같은 체크포인트, 5 env) | −4.0 ~ +17.7° | **−0.67 °/°** |

부호가 같고 크기도 같은 급이다. **관측 구성·관절 순서·부호·스케일에 이식 오류는 없다.**
(로그 기반 사상 비교 = 계약 검증이며 폐루프 성능 증명이 아니다.)

### 2. 명령 → 실측 지연이 시뮬보다 크다 — 대조 실험 진행 중
같은 추정기(상호상관 최대, 광대역 구간)로 양쪽을 쟀다.

| | 명령 → 실측 지연 |
|---|---|
| 실물 3회차 6~23 s (힙·무릎·발목 세 관절 모두) | **16틱 = 320 ms** (r 0.80~0.98, 단일 피크) |
| 시뮬 명목(액션 지연 6틱 설정) | 11.4틱 = 228 ms |

차이 약 4.6틱(92 ms). 모터 상태 나이는 중앙 7 ms·최대 24 ms 로, 기록 지연 탓이 아니다.
→ **가설**: 학습의 액션 지연 대역(4~11틱)이 실물보다 낮다.
→ **대조 실험**(지연만 단일 변수로 6 / 9 / 11틱) 실행 중. 지연만 올려 실물 서명
(인계 1 초 뒤부터 전방 단조 기울임, 앞 밀기에서 스텝 0)이 재현되는지 본다.
재현되지 않으면 지연은 원인이 아니라 상관으로 남긴다.

### 3. 2 Hz 진동은 손이 만든 것이다 — 로봇 특성으로 쓰면 안 된다
구간별 명령 우세 주파수: 무보조 0~2.2 s = 0.90 Hz(63 %), 손 접촉 직후 2.5~6 s = 2.00 Hz,
이후 6~23 s = 1.00 Hz(16 %, 사실상 광대역). 2 Hz 는 손이 닿은 직후에만 나타난 과도현상이다.
**손이 폐루프에 들어오면 손 자체의 동역학이 섞인다** — 진동 지표는 보조 구간에서 쓰지 않는다.

## 정정: 평가기 발목 한계 지표 버그
`eval_ground_recovery.py` 가 |발목 명령| 을 **두 발목 soft_max 의 절대값 최소**와 비교했다.
오른 발목 가동범위는 [−39.0, +18.5]° 이고 실제 명령은 −28° 라 해당 경계는 soft_min 인데,
+18.5 와 비교하는 바람에 **정상 기본자세(±28°)가 매 틱 "한계 초과"로 집계**됐다(92.2 %).
관절별 부호 있는 초과량으로 고쳤다(학습 보상 `action_limit_excess` 와 같은 규약).
- 영향 없음: 실물 2회차의 "발목 명령 56.7° > 왼발 soft_max 39.0°" 는 별개 경로(stage8 클램프
  카운터 43회)로 확인된 것이라 그대로 유효하다.
- 영향 있음: 시뮬 보고의 "소프트 한계 초과 틱 %" 수치는 전부 무효 — 재측정 대상.

## 추가 분석 (0923): 실물이 넘어질 때 정책은 발목으로 버티지 않았다

발이 바닥에 붙어 있으면, 힙·무릎을 고정한 채 몸이 앞으로 기울 때 발목 명령은 **기하만으로**
정확히 −1.00 °/° 로 따라간다(평발 유지선). 이 선을 그대로 따라가면 발목은 몸이 축을 중심으로
자유롭게 도는 것을 막지 않는다. **그 선에서 벗어난 양이 정책이 실제로 낸 균형 작용이다.**

잔차 R = 발목 명령 + 1.0 × 피치, 그 기울기 dR/d(피치). 양수 = 기우는 반대로 더 버팀.

| 조건 | 발목 기울기 | **잔차 기울기** |
|---|---|---|
| 시뮬 명목, 지연 6틱, 뒤 18 N 밀기 후 3 s | −0.65 | **+0.346** |
| 시뮬 명목, 지연 11틱, 같은 구간 | −0.36 | **+0.643** |
| 실물 3회차, **손 보조 구간** (2.5~23 s) | −0.61 | **+0.39** |
| 실물 3회차, **무보조 구간** (0~2.2 s, 실제 낙상) | −1.02 | **−0.021** |

**같은 시행·같은 정책·같은 기체인데, 손이 받치고 있을 때는 시뮬과 똑같이 버티고(+0.39),
아무것도 안 받칠 때는 버티는 작용이 0 이다(−0.02).** 피치가 15.3° 기우는 동안 기하 보정을
넘어선 발목 작용은 피치와 무관한 13° 의 채터뿐이었다.

### 한계
무보조 구간은 **단조 기울임 1회**뿐이라 회귀가 약하게만 식별된다. 기울기 −1.02 자체보다,
잔차가 피치와 무상관(−0.021)이고 그 변동이 채터라는 점이 근거다. 확정하려면 무보조 시행에서
기울었다가 일부 되돌아오는 구간이 최소 2회 필요하다.
지연(16틱)은 단조 램프에서 기울기가 아니라 절편만 옮기므로 이 결과를 설명하지 못한다.

### 이것이 가리키는 것
시뮬과 손 보조 조건에서는 정책이 +0.35~0.64 °/° 의 복원 작용을 낸다. 무보조 실물에서는 안 낸다.
**모자란 것은 딱 그 항 하나이고, 파라미터가 하나다.** 정책을 다시 학습해서 이걸 만들려면
세대 하나(수 시간~하루)가 들지만, 같은 항을 명령 위에 더하는 것은 이득 하나를 실물에서
5~10 시행으로 맞추는 일이다.
