# 실물 기동 단순화(정책 ON) — 1005

로컬 구현과 자가시험만 했습니다. 젯슨 배포, 모터·CAN 조작, Isaac 시뮬 평가는 하지 않았습니다.

## 1. 공중 정책 안전 검토 결론: 공중에서는 정책을 돌리지 않습니다

- 학습 분포: G21a와 G24R-a의 env.yaml은 둘 다 `hang_support r0=0`(지지 없음)이고 스폰 z는 0~1 cm(지면 출발)입니다. 두 정책 모두 공중이나 무접촉 출발을 학습한 적이 없습니다. 0918 결정("정책은 공중을 배우지 않는다")과도 일치합니다.
- 오프라인 목 프로브 결과입니다(물리 없음, 몸통 고정, 관절은 명령을 완전 추종한다고 가정). 접촉 0/0일 때 G21a·KE는 1 s 안에 오른 힙을 기본자세에서 **52.9°** 벗어나게 명령했습니다. 같은 조건에서 접촉 1/1이면 10.9°였습니다.
- 젯슨 하드웨어맵이 `guard_mode=data`라서, 공중 정책을 리프트 가드나 발진 가드가 멈춰 주지 않습니다.
- C5 감지기는 기준 자세를 시작 후 1.5 s 안에 캡처합니다. 공중에서 시작하면 공중 자세가 기준이 됩니다. 대조 시험(같은 시나리오에서 `hang_arm`만 바꿈)에서 정책이 공중에서 150틱 돌았고, 착지 뒤 회복 모드가 **2회 오탐**했습니다.
- 결론: 착지가 확인되기 전까지는 정책을 계산하지도 않고 수평 홀드를 유지합니다. 블렌딩은 새로 넣지 않고 기존 1.5 s를 그대로 씁니다. 300 ms 이하로 줄이는 것은 시뮬로 평가되지 않은 배포 체인 변경이고, 1.5 s는 C5 `ref_init_s`의 전제이기도 해서 보류했습니다.

## 2. 코드 변경

- **`rl_bridge_node.py`**
  - `TouchdownGate`를 추가했습니다. 상태는 AIR_CHECK → WAIT_CONTACT ⇄ SETTLE → POLICY 순서입니다.
  - stand 명령에 `touchdown_start`가 있을 때만 이 게이트가 생깁니다. `hang_arm`과 함께 오면 거부합니다.
  - `_td_hold`: 대기 중에는 래치한 홀드를 송신합니다. 홀드 자세가 정책 기본자세와 8°를 넘게 다르면 정지합니다.
  - `_reset_chain_state`: 기존 리셋 블록을 그대로 함수로 옮긴 것입니다.
  - 시작 시점에 러너를 reset합니다. 이력은 백필되고 직전 액션은 0, C5 기준은 착지 뒤 자세로 잡힙니다.
- **`console_state.py`**
  - `policy_on` 선행조건 함수를 추가했습니다.
  - 순서기가 진행되는 동안에는 다른 조작을 막습니다(정지 요청은 예외).
  - 착지 대기 중 브리지가 내는 홀드는 '정책'으로 세지 않습니다(`policy_commanding`).
- **`operator_console.py`**: `start_policy_on`과 `_policy_on_worker`를 추가했습니다. 기존 액션과 기존 게이트, 기존 응답 확인을 그대로 거치며, 실패하면 즉시 멈추고 고장 래치를 겁니다. 텔레메트리에 `start_gate`를 넣었습니다.
- **`robotctl.py`**: `policy-on` 명령을 추가하고, 상태 줄에 착지 대기를 표시합니다.
- UI 버튼, 데모, 테스트 2개 파일도 함께 바꿨습니다.

## 3. 절차 비교

- 종전: 영점 → 공중 자세 → kp150 → 수평 → 착지 → 접지 선언 → 자동수평 → 핸드오프 → 기준점 → ARM → 정책 로드 → stand
- 신규: 영점(prep) → 공중 자세·kp150·수평(`hang`, `level`) → **정책 ON** → 지그 해제
  - 자립 판정 기록(`op_slack_done`)은 지금처럼 운영자가 누릅니다.

## 4. 상태도

```
[사용자] prep → hang → level → 정책 ON ─────────────→ 지그 해제
[콘솔 순서기] 접지마커 → 핸드오프 → 기준점 → ARM → 정책 로드 → stand(touchdown_start)
[브리지] 워밍업 → AIR_CHECK → WAIT_CONTACT(홀드, 정책 0틱)
           ⇄ SETTLE(양발 0.3 s, |ω|<0.3 0.1 s 또는 상한 1 s, 중력 게이트)
           → POLICY(러너 reset, 블렌딩 1.5 s, C5 기준 캡처)
   대기 120 s 초과 / 자세 불일치 / 센서 stale → STOP_ALL(같은 홀드 동결)
```

## 6. 실물 전 위험과 확인할 것 (미검증 / 현장 확인 필요)

- **Isaac 미평가.** 정책은 지면에 정지한 상태에서 출발하도록 학습됐습니다. 낙하 착지 직후 0.4~1.4 s에 정책을 시작하는 경우는 시뮬로 확인한 적이 없습니다. 실물 전에 낙하 출발 평가(착지 기울기 분포 포함)를 권합니다.
- 정책 ON을 누를 때 발이 떠 있어야 합니다. 줄이 아직 하중을 받는 상태에서 양발 접촉이 잡히면, 지지가 남은 채로 정책이 시작됩니다(학습 분포 밖). 지그는 한 번에 완전히 풀어 주세요.
- 패드가 0 또는 1로 고착되면 정책이 시작되지 않고 120 s 뒤 홀드 동결로 끝납니다. 사전에 손으로 양발 접촉 비트를 확인하세요.
- 자동수평 없이 착지합니다. 과거 착지 기울기는 −1~+9°였습니다. 중력 게이트는 17.5°입니다.
- 젯슨의 `hang_stand.py` 상태 파일에 `joint_trim`과 `gait` 키가 있어야 하고, `level_pose.json`이 있어야 합니다. 없으면 정책 ON이 거부됩니다(안전한 쪽으로 실패).
- 정책이 시작된 뒤에는 `guard_mode=data` 규칙이 그대로 적용됩니다.
- 젯슨 배포에는 승인, md5 확인, 젯슨 셀프테스트가 필요합니다.

## 7. 되돌리기

- 운영: 정책 ON을 쓰지 않고 기존 단계별 버튼이나 `robotctl handoff/stand`를 쓰면 됩니다. stand payload가 종전과 같다는 것을 시험으로 고정해 두었습니다.
- 코드: `git revert <이 커밋>`. `touchdown_start`가 없으면 브리지 경로는 종전과 같습니다.
