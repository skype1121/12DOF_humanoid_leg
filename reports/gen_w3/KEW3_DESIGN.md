# KE ↔ W3 합성 러너 설계 — "ge 0 인 동안은 KE, 걷는 동안만 W3" (초안 2026-10-07 17:10, claude2)

> 상태: **설계 문서. 구현 전.** 근거 실험 X1·X2(TRANSITION_W3KE.md §1c)가 통과해야 구현에 들어간다. 구현은 로컬·기본 꺼짐·셀프테스트 포함이며
> 젯슨 배포·서비스 변경·실물 시험은 승인 사항이다(CLAUDE.md). 시뮬 수치는 실물 성공 확률이 아니다.

## 1. 왜 이 구조인가 (측정 근거, 지연 2)
| 사실 | 수치 | 출처 |
|---|---|---|
| 정책 교체 방식(재기동 / 러너 리셋 / 상태 이어받기)은 낙상이 같다 | b18 4.7 / 4.7 / 3.8 %, sf15 17.1 / 15.8 / 17.7 %, 무외란 0 | TRANSITION §5.2 |
| hot-swap 과도는 슬루 안 | 첫 틱 목표 점프 1.1°, \|ω\| p95 0.40 rad/s | §5.2 |
| 재기동의 수동 홀드 창은 최약 상태 | 홀드 중 뒤 18 N 낙상 59.2 % (W3 STAND 12.3 %, KE 1.7 %) | §5.5 |
| W3 STAND 는 KE 보다 밀기에 약하다 | b18 12.0 vs 4.7 %, sf15 99.7 vs 17.1 % | §5.1, STAND_MODE_CMP |
| KE → W3 는 세 방식 모두 깨끗 | 낙상 0/316, 선행조건 0.98 s, 첫 이륙 0.22 s | §5.3 |
| 밀린 직후 정지는 해롭다 | 앞 12 N: 계속 걷기 25.0 % vs stop 53–56 % | §5.4 |
→ 프로세스 재기동과 W3 STAND 구간을 없애고, 전환을 gait 래치(켜기 수락 틱 / 반주기 경계 꺼짐 틱)에 묶는다.

## 2. 구조
```
            step 켜기(감독기 선행조건 통과 + KE 회복 모드 꺼짐)
   KE  ───────────────────────────────────────────────▶  W3 (걷기·회전)
 (G21a 서기 + G24Ra 회복                                  (W3S3d, ge 1)
  + 감지기)        ◀───────────────────────────────────
            stop / step 끄기 → 반주기 경계 ge 0 래치
```
- 세션 시작(`stand`) = 홀드 → KE 인계(기존 경로·기존 근거 그대로: 워밍업·온셋 블렌딩 1.5 s).
- 브리지 노드에서 보면 **W3 세션 그대로**다(체크포인트 키가 W3 키 집합에 속함): `step` 명령·seq·ack·정지 래치·켜기 선행조건(양발 1.0 s·기울기 ≤ 7°·\|ω_xy\| < 0.25 1.0 s)·헤딩 고리·명령 범위가 그대로 적용된다.
  바뀌는 것은 "ge 0 일 때 어떤 정책이 서는가" 하나다.
- 프로세스·ROS 토픽·stage8 스트림은 끊기지 않는다(수동 홀드 창 없음, 블렌딩 없음).

## 3. 러너 계약 (`rl_walking/deploy/kew3_runner.py`, 새 파일)
`KeW3Runner(w3: PolicyRunnerStage4(w3=…), ke: C5Runner)` — 브리지가 쓰는 러너 인터페이스(step·reset·set_gait_enable·_w3_clock·last_obs·last_action·blackbox …)를 그대로 낸다.
| 사건 | 동작 | 시뮬 대응 |
|---|---|---|
| reset() | 두 러너 reset, 모드 KE, want False | 홀드→KE 인계(sab 하네스) |
| KE 모드 틱 | `ke.step()` (감지기·회복 전환·cue 그대로) | KE |
| KE 모드에서 want True | **이 틱에** W3 로 전환: `w3.reset()`(이력 첫 틱 백필·last_action 0·EMA 재시작·클록 리셋) + 슬루 기준 `w3._prev_emitted ← ke 의 마지막 방출 목표` + `w3.set_gait_enable(True)` → `w3.step()` | X1 `--ke_mode reset --pre_*_s 0` |
| W3 모드 틱 | `w3.step()` (클록 래치·리드 발 규칙·헤딩 고리 명령 그대로) | W3 |
| W3 모드에서 want False 이고 이번 틱 뒤 클록 ge 0 | **다음 틱부터** KE: `ke.reset()`(이력 백필·last_action 0·EMA·감지기 새로 — 기준 자세 1.5 s 추종) + 슬루 기준 이어받기 | X2 `--settle fixed --settle_s 0` (1 틱 차 — 시뮬은 래치 틱에 KE) |
- 이어받는 것은 **슬루 기준(직전 방출 목표)** 하나뿐이다. 러너 reset 은 첫 틱에 실측 qpos 를 슬루 기준으로 쓰는데, 실물은 명령–엔코더 추종 오차가 수 도라 그대로 두면 전환 틱에 목표가 그만큼 끌려간다. 시뮬 reset 팔은 체인(슬루·LPF)이 연속이었다.
- 노드의 LPF(`tgt_filt`)·발진 가드·리프트 가드·워밍업·블렌딩 상태는 건드리지 않는다(전환은 러너 안의 일).
- 관측 레이아웃(320)·기본자세·관측 필터 β·클록 주파수가 두 러너에서 같아야 한다(다르면 생성 거부).

## 4. 노드 변경 (최소)
- 새 체크포인트 키(예 `stand_kew3_g21a_g24ra_w3s3d15800`)는 `--experimental-w3` + 새 플래그 `--experimental-kew3` 일 때만 등록. 꺼져 있으면 키 자체가 없다(종전 경로 비트 동일 — 기존 셀프테스트로 확인).
- 켜기 선행조건에 한 줄 추가: KE 회복 모드가 켜져 있으면 거부(사유 표시). 그 밖 판정·래치·ack 는 종전 W3 감독기 그대로.
- 블랙박스: `kew3`(모드·전환 사건) + 기존 `c5`·`w3` 필드. 콘솔 미노출(기동 인자).
- KE 종료 판정(imu / imuH)은 KE 설정값 하나(조기 복귀 유지 0.2 / 0.7 s) — STOPEST §17 결과와 사용자 결정에 따른다.

## 5. 검증 계획
1. 시뮬 근거: X1(KE → W3 즉시 켜기)·X2(래치 즉시 KE) 통과 — **구현 착수 조건**. 이어서 지연 3·4, 외란(b18·sf15) 조건.
2. 단위 셀프테스트(numpy, 스텁 정책): 모드 전환 틱·슬루 연속(전환 틱 |Δ목표| ≤ 슬루)·reset 의미(이력·last_action·EMA·클록·감지기)·불일치 계약 거부·꺼진 경로 불변.
3. 노드 셀프테스트(가짜 ROS): stand → step on → 걷기 → stop → KE → 다시 step on, seq·정지 래치·회복 모드 중 켜기 거부.
4. 롤아웃 동치: 시뮬 전환 추적(eval_transition `--trace_all`)의 관측을 합성 러너에 재생해 행동이 float 수준에서 같은지(기존 `selftest_w3_rollout_parity.py` 방식).
5. 회귀: `reports/regress/run_regress.sh --mode quick`(W3·KE 경로 불변 확인).

## 6. 이 구조가 풀지 않는 것
- 걷는 중 외란: 계속 걷기가 기본이고(앞 밀기), 뒤 밀기는 KE 즉시 인계가 낫다(오라클 시점 9.8 vs 21.1 %). 관측 기반 감지기는 Q6 에서 따로 판정한다. 합성 러너에는 `force_ke()`(래치를 기다리지 않는 인계) 자리만 둔다 — 감지기가 통과하기 전에는 호출하지 않는다.
- W3 걷기 자체의 sim-to-real 간극(지연 ≥ 5 틱, IMU 피치 편향 × CoM, 발목 유격): ROBUST_DESIGN.md.
- 세션 전체 방향 기준(heading): 걷기 시작마다 기준을 새로 잡는다(현행). 세션 기준 보존은 별도 과제.

같은 부품(브리지 `_make_runner` 가 만든 두 러너 + `KeW3Runner` + `W3Supervisor`)의 시뮬 폐루프 동등성은 X6 이 통과했다(TRANSITION §5.10c) — 이 절은 그 부품을 노드에 잇는 배선과 그 계약 검증이다.

### 8.1 무엇을 붙였나 (`jetson/scripts/rl_bridge_node.py`)
- 기동 인자 `--experimental-kew3`. **`--experimental-w3` 와 함께만** 받는다(없으면 exit 2). 합성 키는 W3 키 집합(`W3_CKPTS`·`W3_CMD_LIMITS`)에
  속해 W3 세션의 `step`·seq·ack·감독기·헤딩 고리·감시를 `runner._w3_clock` 으로 그대로 쓰고, 하위 W3 키가 등록돼 있어야 만들어지기 때문이다.
  `disable_experimental_w3()` 는 합성 키도 함께 내리고, 다시 켜면 복원한다(selftest 가 W3 등록을 껐다 켜도 플래그 상태가 유지된다).
- 합성 키 `stand_kew3_g21a_g24ra_w3s3d15800` = `KeW3Runner(_make_runner("stand_w3s3d_15800"), _make_runner("stand_c5kr_g21a_g24ra"),
  handoff="carry", settle_quiet_s=0.5)`. 값은 `KEW3_SPECS` 한 곳. 하위 러너는 기존 `_make_runner` 경로 그대로라 기본자세·관측 필터·env.yaml 요구·
  감지기 설정이 각 하위 키에서만 정해진다. 레지스트리 값(경로 = KE 서기 정책·기본자세·명령 범위)은 하위 키의 것을 가리킨다.
- `--runner-ema-fresh 2` 와 함께면 기동 거부(인자 검사 exit 2 + `_make_runner` 가 모델을 읽기 전에 ValueError + 러너 생성자 거부, 세 겹).
  `--c5-settle`·`--c5-imu-f32` 는 합성 키에서 종전 검사대로 거부된다(평가된 것은 현행 imu 종료 판정뿐). `--c5-overtime` 은 합성 키에서 허용.
- 켜기 게이트 `runner_enable_gate`: 감독기(·감시)가 수락한 켜기라도 `runner.enable_block_reason()` 이 사유를 주면 거부하고 응답 `why` 에 남긴다
  (`_on_cmd_w3`, 감독기 없는 종전 `_on_cmd_base` step 경로 둘 다). 감독기는 그 seq 를 이미 소비한다(재시도는 새 seq — 종전 규칙).
- 기록(합성 키 세션에서만 필드 추가): 블랙박스 `c5` = `runner.blackbox()`(KE 필드 + `kew3`), 디버그·응답 최상위 `kew3` =
  {mode, event, n_to_w3, n_to_ke, ticks, want, block(켜기 차단 사유), since_latch_s·settle_s(정착 대기 진행)}.
  `--c5-overtime` 입력은 합성 러너 `last_mode`(W3 모드에서는 0)라 KE 모드에서만 회복 체류를 센다.
- 꺼져 있으면 `KEW3_CKPTS` 가 비어 레지스트리·명령 처리·블랙박스 스키마가 종전과 같고 `kew3_runner` 모듈은 import 되지 않는다.
  파일이 없는 배포에서 기본 selftest 는 그 항목만 SKIP, `--experimental-kew3` 기동은 노드 생성 전 거부한다.

### 8.3 설계 판단과 남은 결정
- **hang_arm 시작**: 합성 키는 W3 키 규칙대로 거부한다(평가된 시작은 지면 KE 서기뿐). 허용 여부는 사용자 결정.
- **KE 모드 가드 트립**: W3 세션 감독기를 그대로 쓰므로 KE 서기·회복 중 리프트/발진 가드 트립도 지연 동결(양발 지지 확인, 상한 1.5 s)이다 —
  종전 C5 세션의 즉시 동결과 다르다. 서 있으면 같은 틱에 동결된다(selftest). 유지 여부는 사용자 결정.
- **회복 모드 갇힘 → 걷기 켜기 계속 거부**(TRANSITION §5.10b·§5.10c: X6 무외란 316 env 중 4 env 가 10 s 넘게 갇힘, 1 env 는 끝내 못 걸음)는 이 배선에서도 그대로다 —
  게이트는 설계대로 거부만 하고, 자세가 기준으로 돌아오기 전에 운영자가 풀 수단은 재시작뿐이다(`--c5-overtime` 으로 기록·동결은 가능).
  해소 후보 `SwitchDetector(requiet=…)`(c5_switch, 기본 꺼짐)는 합성 키에 넣지 않았다: 합성 키의 KE 는 현행 `stand_c5kr_g21a_g24ra` 그대로다.
  X6b 는 통과했다(TRANSITION §5.10d: 갇힘 3 → 0, 못 걸은 env 1 → 0, 낙상 동일). 채택이 정해지면 `C5_EXTRA` 의 감지기 설정에 `requiet` 가 든 C5 키를 등록하고
  `KEW3_SPECS` 의 `ke` 를 그 키로 바꾸면 된다(한 곳, 미구현·미검증 — 감지기 변형 채택은 KE 단독 배터리가 따로 필요하다는 §5.6h 의 조건 그대로).
- **KE 변형 선택**: 합성 키의 서기 쪽은 `stand_c5kr_g21a_g24ra`(조기 복귀 유지 0.2 s)다. 1007 에 젯슨 콘솔 선택지로 올린 krh(유지 0.7 s)는 본 브리지
  레지스트리에 없다(`deploy/cand/c5krh_1007/` 사본에만). 합성에 krh·requiet 변형을 쓰려면 본 브리지에 그 C5 키를 등록한 뒤 `KEW3_SPECS` 의 `ke` 를 바꾼다(§4 의 imu/imuH 결정).
- **헤딩 고리**: 합성 키도 W3 세션 그대로 켜기 명령의 `heading_loop` 기본값이 True 다. 시뮬 X6·X7 은 고리를 끄고 돌렸다(HEADING_SESSION_1007.md §0·§6) —
  합성 러너 + 고리의 폐루프 평가는 없다. 첫 시험은 `--w3-heading-loop off` 또는 명령마다 `heading_loop: false`.
- **기록 공백**: W3 → KE 인계 틱의 디버그 `obs` 는 null 이다(러너가 그 틱 관측을 두 하위 러너에서 모두 지운다. `raw_action` 은 남는다).
  `kew3_runner._carry` 에 `dst.last_obs = src.last_obs` 한 줄이면 메워진다 — 파일은 건드리지 않고 원숭이 패치로만 확인했다(인계 틱 관측 320 이 남고
  행동 동일, 러너 selftest·브리지 합성 항목 PASS). 반영 여부는 러너 소유자 결정.
- W3 모드 동안 `c5` 의 KE 필드(raw_stand·raw_rec·ref_deg)는 마지막 KE 틱 값 그대로다. 어느 러너가 도는지는 `kew3.mode` 로 본다.
- **미검증**: 젯슨 배포·실물·ROS 실행, Isaac 폐루프(`run_regress.sh`·X6)에서 이 브리지 사본 사용, 콘솔 통합(기동 인자뿐 — `w3_cmd.py status` 는
  `kew3` 를 아직 안 보여 준다), 합성 세션 + `--w3-monitor`·`--w3-hl-fault` 의 노드 수준 시나리오(코어 수준만 확인). 시뮬 수치는 실물 성공 확률이 아니다.
