## 3. 방법에서 배운 것 (다음에 같은 실수를 안 하려면)
1. **같은 설정에 학습 seed 만 바꾼 대조 셋이 요 누적 2.0–3.8 배, 왕복 낙상 0.29–2.13 % 로 갈렸다.** 이어 학습 한 번·체크포인트 하나의 왕복 수치로는 처치 효과를 말할 수 없다.
   처치와 대조를 같은 seed 로 짝지어 셋 이상 돌리고, 대조의 흩어짐을 넘는 효과만 적는다.
2. 체크포인트를 고르는 검증 지표에 왕복·버튼 대본·정지 전환을 넣는다. 15800 은 좋은 구간에서 고른 체크포인트였다(같은 학습의 15700–16193 이 8.7–11.7 %).
3. 팔 자신의 목표(기전 기준)와 "해치지 않음"(S1–S5)을 따로 등록해 둔 것이 쓸모 있었다 — 토크 한계 무작위화는 기전을 통과하고 S1 에서 걸렸다.
4. 표본 크기를 기준과 함께 적는다. 칸당 109 env 로 +3 %p 를 보려던 X17 은 가를 힘이 없었다.
5. **평가 구성과 배포 구성을 한 줄씩 대조한다.** 합성 키의 감지기 옵션이 평가에만 켜져 있었고, 계약 감사가 "기본 꺼짐 선택 기능"으로 분류해 놓쳤다.

## 4. 다음 세대에 대한 제안 (우선순위 순, 전부 [결정])
1. **하드웨어 원인부터**: H0(드라이버 전압 한계 읽기) → H1(허브·발목 전압 파형). 강하면 "상한 + 상한을 견디는 정책", 회생이면 흡수 회로 쪽이다. 정책 작업의 방향이 여기서 갈린다(`HARDWARE_P0.md`).
2. **걷기 세대 W4(계약 불변)**: 처음부터 또는 긴 학습으로, 아래를 단일 변경 대조·seed 3 으로 쌓는다.
   - 토크 한계 무작위화 0.7–1.0 + 전진 유인(상한 내성 — 확인된 재료)
   - 무릎 벌점 −4.0(무릎 44° — 확인된 재료). 힙 외전 쪽으로 옮겨 간 병목은 한발 지지 시간 축소(W3S3tD — 설계만 있고 미실행)로 따로 본다.
   - 버튼형 짧은 걷기(0.6–2.4 s)와 잦은 정지가 들어간 명령 분포 — 오늘의 리샘플 4–6 s 는 버튼보다 훨씬 길었다.
   - **명령 0 에서의 흐름을 직접 벌하는 항**(영점 속도 추종) — 묶음이 걸린 곳이다.
   - (전 관절 소프트 한계 클램프는 큰 표본에서 무해로 확인돼 넣을 필요가 없다 — X17c.)
   - 걷는 중 밀기(WD 설계 — 1007 의 W3S4dD 는 G3·G5 불합격, 재설계 필요).
3. **회복**: 상한을 견디는 회복은 한계 무작위화로 안 됐다. 큰 스텝 하나로 받는 구조라 줄일 여지가 없어 보인다(가설). 무릎을 편 서기 자세에서 회복 스텝의 요구 토크가 주는지부터 재 본다.
4. **기본자세 변경(계약 변경)은 지금은 필요 없어 보인다**: 무릎은 보상만으로 20° 움직였다. 서기·회복 정책도 같은 방식으로 움직이는지는 미확인이다.
5. 승격 기준은 그대로 쓴다: `W3_FINAL_SELECT.md` §3(S1–S5) + 토크 상한 0.8 배 왕복(§12).
