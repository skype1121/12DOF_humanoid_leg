## 1. 왜 지금 Stage 3 인가(측정 사실)
1. W3 태스크 command term 은 `heading_command=True`·`ang_vel_z=(0,0)` 이다.
   `_update_command` 가 매 틱 heading env 의 wz 를 clip(·, 0, 0) = 0 으로 덮는다. 그래서 정책 wz 응답 이득이 ≈ 0 이다(W3-A3 +0.001, W3S1b +0.003).
   W3 전 세대가 wz = 0 만 보고 학습했다. 단위시험 [D] 에서 Isaac Lab 원본 코드로 재현했다.
2. 요 표류는 env 고정 편향이다(30 s 30–40°, DR 명목 고정 시 13°). 지지발 비틀림 미끄럼으로 나타나고, 스윙 배치가 이미 보정 채널이다.
   hip_r 억제는 오히려 악화시켰다(30 → 58°) → 정책 내부 벌점으로 닫는 경로는 kill.
3. 오픈소스 표준은 wz 추종 보상을 명령 0 을 포함해 항상 켜 두고, 정책 밖 헤딩 P 고리 wz = clip(0.5·wrap(ψ* − ψ))를 둔다. 학습·평가·배포에 같은 고리를 쓴다.
   → 헤딩 고리의 선행 조건은 **정책이 wz 에 응답하는 능력**이다. 이것이 Stage 3 이다.

## 7. 배포 계약 영향(실물 전 필수, 지금은 미반영)
- 외부 헤딩 P 고리(kp 0.5, ±0.4, ψ* = 걷기 시작 요 + wz 적분)를 배포 러너에 넣어야 한다. IMU 요 적분을 쓰고, 실물 IMU 요 표류율은 현장 확인이 필요하다. selftest 에 eval_w3 `--heading_loop` 와의 식 동치 검사가 필요하다.
- wz < 0 오른발 리드 규칙은 위상 생성기 계약 변경이다(S2 vy 규칙과 함께 w3_deploy.py 반영).
