## 1. 0912 와 달라지는 근거 (MEASURED / 계산)
0. **(0913 06시 정정, 가장 중요) 왼발 접촉 비트는 세션 내내 가짜였다.** 고착 패드 L[2]가 공중에서도 587 카운트(임계 200 초과)를 내 왼발 비트가 항상 1 이었고, T5 는 왼발의 살아있는 패드 3채널이 처음부터 끝까지 0 이었다. 즉 정책은 왼발이 떠 있어도 '양발 접촉' 으로 알았고, 오른쪽으로 느리게 구를 때 왼발 이탈에 반응하지 못했다(접촉 상실 직전엔 오른발 앞바깥 패드 하나만 남음). 왼쪽으로 굴렀다면 정상 패드가 0 을 내 정책이 반응했을 것 → 5회 모두 오른쪽인 이유의 유력 후보. **L[2] 제외(`left_pad_bias`)와 죽은 채널 진단은 이 기전을 직접 제거한다** — 이번 시험의 1순위 변경.
1. **가드는 원인이 아니었다.** 5회 모두 가드 정지 0건(T1 리프트 가드 제외). 정책은 넘어지는 동안에도 살아 있었다. 가드는 바꾸지 않는다.
2. **정책은 느린 기울기(≤1 °/s·≤5°)에 반응하지 않았다**(롤 관절 목표 변화 ≤1.1°, 이득 0.11~0.13 °/°). 시뮬 v5 는 줄이 걸린 동안 접촉 천장 근처(홀드 14.6~15 보다 0.4~0.7 Nm 아래, 스텝 폭주)까지 버티지만, 줄이 없어진 뒤 상수 롤 모멘트 6 Nm 에는 31~55 % 만 생존(정적 토크 유지 능력 약함).
3. **부분지지에서 버틸 수 있는 외란 모멘트는 발 하중에 비례한다**(시뮬 홀드 천장 14.6~15 Nm @50 % 지지 = 접촉 한계). 지지가 남아 있는 시간이 길수록 작은 모멘트에도 넘어진다.
4. 구맵 영점 오차(힙 요 −7.5/−6.3° 등)는 제거됐다(재캡처). IMU 는 수평에서 lat +1.3° 를 낸다(장착 편향).

## 2. 현장 사전 확인 (0911 §3 에 추가)
- **영점 확인은 지그 자세에서**: 콘솔 `영점 확인 12/12`, 잔차 3° 안. 3° 밖이면 배수 보정 우선, 재캡처는 지그 자세에서만(승인).
- **무동력 관절 유격 실측(0913 신설)**: stage8 **ARM 전**(재기동 직후 읽기전용 폴링)·정책 정지 상태에서 `python3 jetson/scripts/play_probe.py --host 172.16.35.89 --out ~/logs/play_0913.json` 을 띄우고, 관절명을 고른 뒤 링크를 양 끝까지 **살짝** 밀며 폰 경사계 각도를 두 번 입력한다 — 유격 = 링크 폭 − 엔코더 폭, 콘솔 상태 GET 만(모터 명령 없음). ARMED·정책 live·엔코더 미갱신이면 도구가 거부하거나 무효로 기록한다.
- 피치 관절(hip_f·knee·ankle_f) 6개를 관절당 2회 먼저 재고 JSON·표를 남긴다(횡은 여유 있을 때). 판정은 하지 않고 기록만 — 참고로 시뮬은 피치 유격 2° 84~92 %·3° 8~23 %(`analysis §4.8`, 시뮬 값이며 실물 성공 확률이 아니다).
- **착지 뒤 콘솔의 발 접촉 카드(패드 8칸 미니 표: 초록=눌림, 회색 빗금=dead 후보, 0913 추가)로 왼발의 살아있는 채널(L0·L1·L3)이 실제로 눌리는지 확인**(고착 L[2] 제외 뒤 왼발 접촉 표시는 라이브 채널에서만 나와야 한다). 왼발 라이브 채널이 0 이면 왼발은 떠 있는 것 — 그 상태에서 방출하지 않는다.
- **오른발 뒤바깥 패드(right[3])·왼발 안쪽 2채널이 0 카운트인지** 손으로 눌러 확인(0912 지그 접지에서 0 = 죽은 채널 의심). 죽은 채널(0 고정)은 any-pad 판정에서 '접지인데 비접촉' 오판을 만들 수 있다(그 채널만 눌리는 자세) → 리프트 가드 입력이므로 정비 대상. 어댑터가 `dead_mask` 로 후보를 표시한다(0913). 패드는 접촉 여부용이다.
- **줄 연직**: 착지 직전 로봇이 앵커 바로 아래에 있는지(다림추 또는 카메라 정면 뷰). 앵커 10 cm 오프셋 = 50 % 지지에서 약 6 Nm 롤 모멘트(천장 15 Nm 의 40 %).
- **앵커(현수 프레임)가 방출 중 움직이지 않는지**: 사진의 알루미늄 프로파일 프레임은 캐스터 위에 있다. 시뮬은 줄이 걸린 부분지지에서 어떤 정적 조건으로도 v5 를 못 넘어뜨렸지만, **앵커의 횡 이동 2 cm/s 는 33 s 안에 롤 낙상**을 만든다(0912 드리프트 스윕). 방출 중 하중이 프레임에서 로봇으로 옮겨가며 캐스터 프레임이 몇 cm 굴러가면 같은 조건이 된다(가설). 캐스터 잠금·프레임 고정, 카메라에 프레임 다리가 보이게.
- **카메라**: 발·줄·후크·윈치 손이 한 화면에. 윈치 이벤트 버튼(▶ 방출 시작 / ⏸ 정지 / ↥ 재인장 / ✓ 느슨)을 반드시 누른다 — 0912 는 5회 모두 미기록이라 판정에 구멍.
- 매달려 정지했을 때 콘솔 lat 이 +1.3 ±1° 인지(좌우 정렬; 0912 T5 +1.4 OK). fwd 는 두 줄이 정하므로 정렬 증거가 아님.
- **착지 직후** 콘솔 lat 이 +1.2 ±0.5(수평)인지. 0912 안정 구간은 −0.2~−1.7°(오른쪽으로 0.2~1.7° 굴러 있었음, 1.5° = 왼발 7.6 mm 뜸). 오른쪽으로 굴러 있으면 왼발이 안 실린다 → 재착지.

## 3. 절차 변경 — 방출
- **접지 인계 → 워밍업 완료 → 정책 안정 3~5 s 확인 → 방출은 한 번에**: 양발 접촉 표시 뒤 정책이 3~5 s 안정된 것을 보고(콘솔에는 지지비 표시가 없고 패드 % 는 미보정이라 '60 %' 는 잴 수 없다 — 줄이 아직 하중을 나눠 갖는 상태에서), 나머지를 **3~5 s 안에** 완전히 느슨하게 푼다. 천천히 계속 푸는 방식(0912)은 부분지지 구간(40~63 %)에 8~24 s 머물렀고 5회 전부 그 구간에서 넘어졌다. 근거는 물리 논리(중립 구간 체류 최소화)이지 시뮬 성공률이 아니다 — 시뮬은 느린 방출도 97~99 %(v5)로 벌하지 않는다(`analysis §4.11`). v6 를 쓰면 2 s 급 방출은 −8 pp 라 5 s 안팎이 무난.
- 앞·뒤 줄이 같이 풀리게(찰나의 차이는 무시해도 됨 — 승윤님 손 확인 0912).
- 방출 중 줄·윈치를 옆으로 옮기지 않는다.
- 방출 중 중단 기준은 0911 카드 그대로 **좌우 기울기 3° 초과 증가**(또는 |fwd|>12°, 한 발이 눈에 띄게 뜸, 가드 정지) → 즉시 재인장 → 시도 무효 기록(0913 초안의 '5°' 표기는 근거 없는 완화라 철회). 정책이 느린 기울기를 못 잡는 것은 확인된 사실이므로 기다리지 않는다.
