## 0. 요약
- 현행 고리는 "걷기 한 번에 기준 한 번"이고 지시와 일치한다. 합성 러너와 헤딩 고리를 **함께 돌린 실행은 시뮬에도 셀프테스트에도 없다** [코드].
- 문서에 없던 수치: KE 회복 스텝 한 번에 몸통 방향이 수십 도 바뀐다(뒤 18 N |Δψ| 중앙 23°, 앞 충격 40 N 중앙 32°) [계산]. 기준을 그대로 보존하는 안은 회복 뒤 첫 걷기에서 15° 문턱에 바로 걸린다.
- 왕복 대본(X7)에 참 요·위치 기록을 넣었다(기록 전용, `kwloop_*.npz` 의 `yaw`·`xy`) → 구간별 방향 변화를 처음으로 대량 측정한다.
- **첫 실물 시험에 걸리는 것은 세션 기준이 아니라 켜기 명령의 `heading_loop` 기본값이 True 라는 점이다**(§6).

## 5. 검증 실험 제안(판정 기준은 초안, 실행 전에 고정할 것)
- **HD0**(반영함): X7 에 요·위치 기록만 추가 — 걷기·정지 전환·KE 서기·밀기별 Δψ 분포와 5 구간 뒤 누적.
- **HD1 현행 규칙에서 고리 켬 대 끔**: X7 대본, nd, seed 1–3. 판정 초안: 켬이 끔 대비 낙상 짝 차 ≤ +1 %p ∧ 비회전 구간 |Δψ| 중앙 절반 이하 ∧ 고장으로 끊긴 비회전 구간 ≤ 2 %.
- **HD2 재개 초기 오차 용량–반응**: KE 서기에서 걷기 한 번, 래치 직후 ψ* 에 e₀ ∈ {0, ±5, ±10, ±20, ±30}° 를 더함. 안전 재개 창 = e₀ = 0 대비 낙상 짝 차 ≤ +1 %p ∧ 첫 3 주기 고장률 증가 ≤ 2 %p 인 최대 |e₀|.
- **HD3 방식 비교**: 현행 / 보존 / 보존 + 재개 창, 표류 0·2.5·5 °/min, nd·push.
- 도구에 필요한 것: `eval_transition_kw.py --runner_loop` 가 지금은 `heading_loop: False` 고정이고 `BridgeCore` 를 거치지 않는다 → 합성 키가 브리지에 연결되면 `BridgeCore._w3_cmd_step` 을 env 마다 불러 고리·고장 처리를 배포 코드 그대로 넣는다.
- 하네스 주의: 전환 하네스는 지지 롤 램프가 켜져 있고(`--ramp_off` 로 끔) 램프는 무고리 요 표류를 두 배로 만든다(REVIEW §0-9) → 방향 지표는 켬·끔을 함께 보고.
  검토자가 parity 녹화(다른 태스크·조건)에서 본 "램프 켬에서 자이로와 자세 변화 불일치"는 전환 하네스 실행에는 없었다(TRANSITION §5.14 점검: 관측 자이로 평균 |ω_xy| 중앙 0.010 rad/s, 램프와 무상관).

## 6. 첫 실물 시험에 영향이 있는 것 / 없는 것
**있는 것**(사용자 결정·계획 반영 항목):
1. `step` 켜기의 `heading_loop` 기본값이 True 이고 브리지 기본도 고리 켜짐이다. 계획서 T2·T3·T5 에는 값이 없어, 그대로 치면 IMU 요와 wz 부호를 확인(M2·T6)하기 전에 고리가 15°·120 s 문턱과 함께 돈다.
   단계별로 `--no-heading-loop` 를 적거나 T1–T6 세션을 `--w3-heading-loop off` 로 띄울 것.
2. T6 의 확인 필드 `w3_cmd.hl_on` 은 회전 중에도 True 로 남는다 — 실제 비활성은 `w3_cmd.hl.latched` 로 본다.
3. 고리를 끈 단계에서는 걷는 동안 몸이 돈다(시뮬 30 s 평균 26–55°, 방향은 개체마다 고정). 줄 꼬임·테이프 이탈을 실패로 읽지 않게 카드에 적을 것.
4. T7 의 오정지 빈도를 인용할 때 조건(램프 켬 30–41 %/60 s, 램프 끔 0.8–8 %/120 s)을 같이 적을 것.
