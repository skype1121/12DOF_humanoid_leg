## 공통 시작 절차 (모든 정책 단계)

`ZERO HANGING → LEVEL REFERENCE POSE → POLICY ON → JIG RELEASE → TEST`

1. **기록 시작**: 콘솔 세션 기록(`timeline.jsonl`)·브리지 블랙박스·영상 2 대(측면·정면)를 **첫 제어 조작 전**에 시작. 영상 시작 직후 동기 이벤트(운영자 이벤트 버튼 + 화면에 보이는 동작) 1 회.
2. **ZERO HANGING**: 매달림(발 무접촉)에서 `boot_pose_check` 통과 확인. **영점 쓰기는 하지 않는다**(재캡처는 이 계획 범위 밖, 필요하면 별도 승인·`zero_anchor.py` 배수 보정 우선). 하드웨어맵 변경이 있었으면 stage8 재기동 확인.
3. **LEVEL REFERENCE POSE**: 기준 자세(CROUCH_V5)로 느린 램프·슬루 제한 하에 착지, 자동수평으로 몸통 수평. 줄은 인장 유지.
4. **POLICY ON**: 브리지 `{"cmd":"stand"}` → W3 정책 STAND(ge 0) 시작. 워밍업·블렌딩 완료와 `rl_bridge_ack` 수락을 확인한다(버튼 클릭 ≠ 동작 완료). 줄은 아직 지지.
5. **JIG RELEASE**: 단계가 요구할 때만. 줄을 한 번에 느슨하게 하고, 운영자가 **모든 줄 느슨**을 확인해 이벤트로 기록. 그 순간부터 자립 타이머.
6. **TEST**: 단계별 명령. 끝나면 §2 공통 회수.

### 공통 회수 절차 (양보 불가)

- **정지의 의미 구분**: `step enable:false` = 다음 반주기 경계에서 서기(정책 계속) · `stop` = 끄기 + 정지 래치(정책은 서기 유지) · `estop` = 즉시 STOP_ALL(동결 유지, 토크는 유지) + 정지 래치 · `release_all` = 토크 해제.
- **순서**: ① 줄 인장(운영자 확인 이벤트) → ② 콘솔 스택 종료(콘솔이 띄운 것만, 명시 PID) → ③ **그 다음에만** 필요 시 release_all. 동시 실행 금지. 굽힌 관절 즉시 릴리즈 금지(회생 과전압 이력).
- 넘어지는 중이면 **회수가 데이터보다 우선**: 운영자는 줄·손으로 즉시 받는다. 해당 시도는 무효/실패로 기록하고 낙상을 기다리지 않는다.
- 낙하·큰 충격 뒤에는 다음 시도 전 매달림에서 `boot_pose_check` 재판정(무전원사이클 프레임 시프트 이력).

### M1. 실효 지연 (LATENCY_STAGE_1006 절차 그대로)

### M2. IMU 요 정지 표류율

- 상태: 줄 건 서기, **정책 없음**(stage8 인수 홀드). 바닥에 몸통 방향 기준 테이프 + 정면 영상(실제 회전이 없음을 확인).
- 시간: N = 10 분 [가정]. 처음 1 분은 버리고 9 분 선형 기울기로 표류율 r [°/min] 산출, 순간 점프(> 1° 한 틱 변화 [가정]) 수 기록.
- 이어서 T1 의 정책 서기 구간에서도 같은 값을 다시 본다(진동이 표류를 바꾸는지 대조).
- **고리 문턱 사전 규칙**: 120 s 동안 IMU 표류가 고리 오차 문턱 15° 의 1/3 이하가 되도록 r × (timeout/60) ≤ 5° [가정 배분]. 즉 r ≤ 2.5°/min 이면 15°/120 s 유지, 그보다 크면 `timeout_s = 300/r` 초(5–300 범위)로 줄여 D7 에 기록. 점프 > 0 이면 T7 보류·원인 확인.
- 해석: 헤딩 고리는 IMU 요를 따라가므로 IMU 표류 r 은 그대로 실제 방향 표류가 된다. 시뮬 120 s 2.2–2.4° 는 IMU 이상 없는 값이다.

### M3. 무릎 강성 k 식별 (한 발 정적 하중)

- 목적: odicw 무릎 보상 k̂ 42 [가정] 확인. 근거: 0919 폰 수평계 실측 양발 서기 무릎 숨은 굽힘 +10~12.6°, k ≈ 32–45 N·m/rad [측정, 2 점].
- 상태: **정책 없음**, stage8 홀드, 줄 인장 지지. 한쪽 발만 접지 — 측정할 발 아래에 3–5 cm 블록 [가정]을 두고 매달린 상태에서 줄을 내려 그 발만 닿게 한다(반대 발은 공중). 몸통 기울기는 줄로 제한, 운영자 손 대기.
- 하중 단계: 무하중(매달림) → 줄 하강 2–3 단계(부분 하중) → 줄 허용 최대. 단계마다 10 s 정지 유지.
- 측정: 링크 무릎각 = 허벅지 기울기 − 정강이 기울기(폰 수평계, 0919 방식), 엔코더 무릎각 = stage8 status, 무릎 토크 = 블랙박스 `tau_est_nm`(관절 프레임 = direction × 모터). 한 단계에 수평계 2 회 읽기.
- 산출: k = Δτ / Δ(링크 − 엔코더), 단계 간 기울기. 무하중의 링크 − 엔코더 = 고정 오차(0919 에 +0.5° [측정]).
- **판정 규칙(사전)**: 왼·오 각각 k 가 30–60 N·m/rad 안이면 k̂ 42 유지(재생에서 k̂ 30–60 의 끄기 시각 7/7 동일 [측정]). 밖이면 회복 세션 전 측정 k 로 `odicw_real_replay.py` R1–R3 를 오프라인 재실행하고 통과해야 진행.
- 함께 기록: 홀드 중 무릎 tau_est 잡음 σ(재생 기준 0.04–0.13 N·m [측정]), status_age.
- 현장 부담이 크면(승윤님 1002 의견: 정밀 측정 어려움) 하중 단계를 2 개로 줄인다. 그래도 수평계 링크각은 필요하다.

### M4. 발 패드 점검 (R3 중심)

- 상태: 매달림(무하중) → 줄 지지 양발 서기, 정책 없음.
- 매달림 30 s: 8 패드 원값 기록, 오프셋(L1 85·R2 15 포함)과 잡음 폭, 고착·0 값 여부.
- **R3 배선**: 매달림·접지 각각에서 케이블을 손으로 천천히 흔들며 20 s 기록 — 값 튐·0 고착·끊김이 있으면 배선 결함으로 기록.
- 하중 응답: 줄 지지 서기에서 운영자가 몸통을 앞/뒤/좌/우로 작게 기울여(줄 유지) 각 패드가 눌림에 응답하는지 본다. 손누름 단독 점검은 쓰지 않는다(캡 이탈 결함 때 무효였던 이력).
- 합격: 각 발에서 접촉 0/1 이 매달림 = 0, 서기 = 1 로 안정. R3 결함이어도 오른발 나머지 3 패드로 접촉 비트가 안정이면 진행 가능 — 단 **R3 를 dead_mask 로 뺄지는 [결정]**(조용히 0 으로 대체하지 않는다).
- 금지: 눌린 패드 수·원값 합을 하중 비율·CoP 로 해석하지 않는다(W3 켜기 선행조건의 '양발 접촉' 은 좌우 0/1 비트만 쓴다).

## 2. 단계별 시험

모든 단계 공통:
- 진입 전 직전 단계의 합격 기록과 영상 확인. 한 단계를 같은 세션에서 최대 3 회 [가정] 시도, 실패 2 회면 그 세션은 거기서 멈추고 블랙박스 분석 뒤 다음 세션.
- **중단 조건(공통)** [가정 수치]: 몸통 기울기 > 10° 가 0.5 s 지속 · 같은 발 연속 2 회 이륙(교대 붕괴) · 발 끌림/미끄러짐이 영상·운영자에게 보임 · 떨림·소음 · 가드 기록(data 모드) 발생 · 헤딩 고리 고장 이벤트(`w3_hl_fault`) · 예상 밖 ack 거부 · 센서 신선도 경고. → 운영자: `stop`(걷는 중) 또는 `estop`(넘어지는 중) + 줄 인장 → 공통 회수.
- 명령 사이 간격 ≥ 1 s(브리지 강제), 명령 값 램프 금지.

착지 · 방출 시작/정지 · **모든 줄 느슨 확인** · 재인장 · 손 보조(있으면 무조건) · 밀기(시각·방향·소/중 주관) · stop/estop 발행 · 회수 시작 · 시도 무효 사유.

### 자립 판정 규칙

- **자립 성공** = 모든 지지 줄 느슨 + 외부 보조 없음 상태로 5 s 유지. 30 s 유지는 별도 집계.
- 타이머는 운영자의 **모든 줄 느슨 확인 이벤트 이후** 시작. 손 보조·재인장·가드 정지가 생기면 그 시도는 무효/실패.
- 판정은 운영자 확인 + 영상 + 자세·접촉·제어 기록을 함께 본다. 단일 IMU 화면이나 접촉 비트만으로 선언하지 않는다. 미보정 발력%·CoP 는 쓰지 않는다.
- 결과를 세 층으로 구분해 보고: **정책 시작 성공 / 부분지지 유지(T2) / 완전 자립 성공(T1·T3 이후)**. 걷기 단계는 그 위에 "명령 부호 정답·교대 유지·정지 후 자립" 을 따로 적는다.

- **T2(줄 인장 부분지지 걸음)는 부하를 낮춘 걷기가 아니다.** 시뮬에서 체중의 20–35 % 를 받쳐도 걷기 최대 부하가 거의 그대로였고(서기의 9.8–9.7 배, 받침 없음 10.0 배), 50 % 에서는 걸음이 무너졌다(`TORQUE_BUDGET_1007.md` §19b — 줄을 중력 감소로 이상화한 모형).
  T2 는 v1 대로 계약·순서·리드 발 확인 단계로만 쓴다. P0 가 풀리기 전의 T2 는 권하지 않는다(v1.1 의 권고 유지).

### D. 시뮬에 없던 실물 조건 — 전 관절 소프트 한계 클램프
- 실물 stage8 은 전 관절의 목표각을 `config/joint_limits_12dof.json` 의 soft 한계로 자른다. 학습과 종전 시뮬은 발목 앞뒤만 잘랐다. 시뮬에 넣어 보니 **걷기 왕복·서기·회복 모두 차이가 없다**(회복은 팔당 860 env: 뒤 밀기 9.8 % 대 8.7 %, 앞 램프 13.1 % 대 13.4 % — `TRANSITION_W3KE.md` §5.20f). 작은 표본에서 보였던 "회복에 유해"는 흔들림이었다.
- 회복 중 오른 힙 굴곡 목표가 soft −40.7° 를 자주 넘는다(왼쪽은 45°). 실물 1007 에서도 9 틱 잘렸다. **표는 바꾸지 않았고, 넓힐 근거도 없다.**
- 회복 세션(R)의 기록 항목에 추가: stage8 status 의 `soft_clamp_counts` 를 세션 전후로 적는다(어느 관절이 몇 번 잘렸는지).

### D2. 접촉 비트와 걷기 버튼 (X19 — `TRANSITION_W3KE.md` §5.22b)
- 걷기 정책은 접촉 비트의 지연·채터·짧은 누락에 낙상이 늘지 않는다(시뮬). 걸리는 곳은 **켜기 선행조건(양발 접촉 1.0 s 연속)** 이다: 비트가 초당 한 번꼴로 튀면 버튼 수락이 46 %, 한쪽 패드가 0 이면 전부 거부된다(안전한 쪽).
- 실물 블랙박스 5 세션의 접촉 비트를 같은 조건에 넣으면 4 세션은 91–100 % 수락, 1005 22:03 세션(왼발 접촉 비트가 89 % 동안 0)은 14 % 다 [측정 — 비트만. 패드 고장인지 하중이 없었는지는 미확정].
- **M4(발 패드 점검)는 걷기 세션의 필수 선행조건으로 올린다. 특히 왼발.** 시작 전에 서 있는 동안 양발 접촉 비트가 10 s 끊기지 않는지 콘솔에서 본다 [가정 수치].
- 걷기 버튼이 "양발 접촉 … < 1 s" 사유로 거부되면 패드 신호를 본다. 선행조건 문턱은 바꾸지 않는다(가드). 채터에 덜 민감한 선행조건으로 바꿀지는 [결정] — 바꾼다면 시뮬 재평가가 먼저다.
